## 1. 目标与成功标准

**目标**：面向 HR/面试官的求职作品集博客，大二建站、大四前持续运营，同时承载技术文章。

**成功标准**：
1. 2 周内公网可访问（受备案周期制约，见 §10，以"开发完成待备案"为准）
2. 简历可放置博客链接，含网页简历 + 项目展示 + 时间线
3. 长期：每周 ≥1 篇文章，搜索引擎可收录

## 2. 决策记录（已确认，不再讨论）

| 决策点 | 结论 |
|---|---|
| 定位 | 求职作品集为主，文章为辅 |
| 发布方式 | 在线后台编辑（动态博客） |
| 部署 | 自有阿里云 ECS（大陆）→ 域名需 ICP 备案 |
| 开源底座 | gin-vue-blog 深度魔改，节奏"先上线后深挖" |
| UI | 卡片式现代风，明暗跟随系统，轻动效 |
| 功能范围 | 基础档 + 写作档 + giscus 评论 + Umami 统计 + 时间线 + GitHub 热力图 + 暗黑模式 |
| 数据 | MySQL；图片存服务器本地磁盘 |
| 成本 | 域名 ~¥30-80/年，其余 0 元 |

## 3. 总体架构

```
访客/面试官浏览器
   │  https://blog.example.com
   ▼
┌─ 阿里云 ECS（大陆，Ubuntu，2核2G/4G）──────────────────┐
│  Caddy :80/:443（自动 HTTPS，反代 + 静态托管）           │
│   ├─ /            → gin-blog-front 构建产物（静态）      │
│   ├─ /admin/      → gin-blog-admin 构建产物（静态）      │
│   │                  + Caddy BasicAuth 第一道门          │
│   ├─ /api/*       → gin-blog-server（Go/Gin，仅内网端口）│
│   └─ umami 子域    → Umami 统计（Node，Phase 3 上）       │
│  MySQL 8（Docker 内网，不暴露公网）                       │
│  Redis（Docker 内网，设密码）                             │
│  giscus 评论 = GitHub 托管，零部署                        │
└─────────────────────────────────────────────────────────┘
```

**内存预算（按 2G 最坏情况）**：系统+Docker ~300MB，MySQL ~350MB，Redis ~50MB，Go API ~80MB，Caddy ~30MB，Umami ~250MB（Phase 3 才上）。合计 ~1.1G，**加 2G swap 兜底**；若是 2核4G 则从容。

**域名规划**（备案以主域为单位，子域随意加）：
- `blog.example.com`（或裸域）— 前台
- `admin.example.com` — 后台管理，加 BasicAuth
- `umami.example.com` — 统计（Phase 3）

## 6. 分阶段施工计划

**Phase 0 环境与备案（本周，以你为主）**
1. 阿里云控制台确认：实例**计费方式是否包年包月且剩余 ≥3 个月**（备案服务码的前提）、地域、镜像系统（建议 Ubuntu 22.04）
2. 阿里云买域名（`.com`/`.cn` 对备案最稳）+ 实名认证
3. 提交 ICP 备案（个人备案，用途写"个人博客/技术分享"），周期 1~3 周
4. 准备素材：头像、自我介绍、项目清单（名称/简介/截图/GitHub 链接/技术栈）、简历 PDF

**Phase 1 开发与部署（与备案并行，1~2 周，以我为主）**
1. fork + clone + 本地 `docker compose up` 跑通全栈
2. UI 换皮：卡片式现代风 + 明暗模式
3. 录入初始内容：关于我、≥3 篇文章、项目占位
4. 服务器初始化：swap、Docker、安全组（仅 22/80/443）、SSH 密钥登录
5. 部署 compose + Caddy；**备案期间用 `http://IP:端口` 自测**（大陆未备案域名 80/443 会被拦，这是规定不是 bug）
- 验收：IP 自测全功能可用

**Phase 2 上线 + 第一波魔改（备案通过后，1~2 周）**
1. 绑域名 + Caddy 自动 HTTPS，正式上线
2. 按 §5 完成：简历页、Project 模块、时间线、giscus、GitHub 热力图
- 验收：简历放上博客链接，公网全功能可用

**Phase 3 第二波魔改（第 2 个月，按兴趣推进）**
Umami 统计 → 站内搜索 → 通读 Go 后端源码 → 自研 1~2 个个性模块（说说页/读书页/一言等）
- 验收：浏览量可见，至少 1 个完全自研模块上线

**Phase 4 持续运营（长期）**
每周 ≥1 篇文章（用模板降低写作摩擦）、SEO 收录、RSS、CI 自动部署、友链页
- 验收：月更 ≥4 篇，搜索引擎能搜到你的名字

## 7. 安全设计

- 安全组只开 22/80/443；SSH 仅密钥登录、禁密码
- 后台双重防护：Caddy BasicAuth（第一道）+ 上游 JWT 登录（第二道），且改非默认路径
- MySQL/Redis 仅 Docker 内网通信，公网不可达；Redis 设强密码
- 后台账号强密码；上线前做一轮端口扫描 + 弱口令自查

## 8. 运维：备份与更新

- cron 每日 `mysqldump` 全库 + `uploads/` 目录打包，本地保留 7 天
- 每周备份传 OSS（可选，~¥1/月）或手动下载
- Phase 2 末做一次恢复演练（备份真有用 = 恢复成功过）
- 上游更新：`git fetch upstream` 按需 cherry-pick，不盲目 merge
